# Automate my working style

Turn demonstrated working preferences into a short skill. Use the installed skill-creator guidance. A request to discuss this process does not authorize mining history or editing instructions.

## Gather evidence

- Find the existing owner before writing: personal skill, project instructions or a specific workflow. Update that owner; avoid a second source of the same rule. Edit the owning source repository rather than a managed installation copy.
- Start with this conversation and user-named threads. Use supported T3 tools to read threads; list within the current project only when needed to find relevant history. Do not scan unrelated chats or private runtime databases. If supported history is unavailable, report the gap and use supplied context.
- For a refresh, focus on changes since the previous revision. Keep a short evidence list with source thread links and dates, outside the reusable skill. Use returned T3 links verbatim.
- Separate explicit preferences from inferred patterns. A clear instruction needs no repetition. An inferred convention needs support across independent conversations; conflicting or one-off behavior stays a question, not a rule. Keep personal and project conventions scoped.

## Write

- Ask only about consequential ambiguity. Do not repeat a questionnaire when the user's direction is already clear.
- Keep instructions that change a decision. Use direct verbs and complete sentences. Link existing procedures instead of restating them. Preserve rules the user has not contradicted.
- Draft a personal mode only when several conventions belong together. A narrow preference belongs in its existing workflow. Do not change global instructions, activation policy or delegation defaults unless requested.
- Follow the requested stage: a proposal remains a proposal; an authorized edit proceeds without another routine approval. Neither grants access to new sources, personal-memory writes, publication or release.

## Check

Validate frontmatter and local references. Review whether each new rule has a source, correct scope and an observable effect. For consequential behavioral rules, use the installed t3-eval skill when a trial is requested; subjective tone still needs the user's judgment.

**Reply:** what changed, where it lives, the evidence behind new conventions, unresolved conflicts and whether it is drafted, installed or published.
