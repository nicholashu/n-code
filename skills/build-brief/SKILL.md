# Build brief

Read the agreed discussion, ticket or spec, and project instructions. Preserve confirmed decisions and any pending interview confirmation. Separate decisions from suggestions and assumptions.

Write a short brief that states:

- The required behavior, preserved behavior and scope.
- What must pass and what evidence will prove each requirement.
- The delivery stage, target branch, required artifacts and release permissions.
- Any unresolved choice that changes scope, acceptance or authority.

Use the existing task or spec. Keep detail there and the brief to about one screen. For a large task, identify the first slice that can be verified on its own.

Choose verification from the task's acceptance criteria and risks. Reuse existing checks that cover them. Keep the brief focused on the behavior to deliver.

Find repository facts and commands yourself. Follow the project's writing-tests guidance for test work.

Ask only about unresolved decisions that affect the result. Reuse interview answers and existing approvals. Update affected requirements when scope changes.

If asked only for a brief, stop there. Otherwise continue authorized work without requiring the user to resubmit or approve it again. Preserve release holds. Tie final evidence to the checked revision and environment, and report anything unverified.
